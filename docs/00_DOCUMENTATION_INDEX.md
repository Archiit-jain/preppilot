## Developer documentation

Documentation of the system **as built** lives in [`developer/`](developer/).
The documents above are the specification — what PrepPilot was meant to be, and
the requirements baseline. The developer set describes what exists, why, and
where it falls short. Start with
[`developer/LIMITATIONS.md`](developer/LIMITATIONS.md).

## Strategy

Printable documentation should contain teacher-facing project information, DFDs, architecture, workflows, technology stack, testing and future scope.

Developer documentation should contain implementation-level details, schemas, APIs, synchronization, security and development procedures.
